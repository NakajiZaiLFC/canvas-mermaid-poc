`submission.html`と`../output/pdf/canvas-submission-draft.pdf`は提出原稿です。実AIの検証記録とIMEの確認を反映して、配布済みの正式書式へ転記・照合してください。申し込みや提出は行っていません。

## 審査観点との対応

公開ページの本選審査は5観点です。一次審査の配布書式とは区別します。

| 観点 | 現時点の説明・証拠 | 残る確認 |
|---|---|---|
| 課題 | 会議中の図形配置・プレビュー往復が説明を止めるという依頼者の仮説 | 当事者への確認、実利用者テスト |
| 技術の役割 | AIはMermaidの専門知識の壁を下げる生成・修復。通常の入力と描画は決定的なプログラムで処理 | 共用クラウドで日本語の生成・修復を実証し、公開版の到達性を確認 |
| 社会的インパクト | 会議・授業・設計レビューに展開できる可能性 | 対象者数・効果・利用頻度の実測 |
| 持続性 | 静的配信・端末内保存。明示実行の共用AIは無料枠と厳しい利用量制限で運用 | 無料枠、実際のAI使用量、保守担当の継続確認 |
| 実装 | 編集・描画・保存・検証・候補承認まで実装。検証記録に自動テストと遅延実測 | 実AI、ネイティブIME、会議受信側の可読性 |

公式ではAIがプロダクトの中核で働くことを条件に挙げています。単に開発でAIを使ったことは条件を満たしません。本アプリでは「記法を知らない人が図を作り直すための生成・修復」をAIの役割として説明できますが、実モデルの成功だけで審査条件への適合や採択は断定しません。高速な基本エディターという設計原則は維持します。

## 提出直前の優先順位

1. 公開版のクラウドAIで生成・修復を試す。モデル導入不要であること、利用上限時も基本編集が使えることを確認する。
2. ネイティブ日本語IMEで変換・候補選択・確定・Undoを確認する。
3. 会議をする当事者に短時間使ってもらい、説明までの時間と操作による中断を記録する。未実施の効果は書かない。
4. 正式書式に照合し、実測結果と審査員が試せる環境の条件を記載して提出する。

PDF再生成: `node scripts/submission-pdf.mjs`。A4一枚であることと日本語の欠落・改ページを画像で確認する。
