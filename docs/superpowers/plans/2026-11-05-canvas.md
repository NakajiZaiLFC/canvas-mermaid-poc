# Canvas Mermaid PoC Implementation Plan

Goal: one canvas for Markdown and Mermaid with local-only optional AI.
Approved in conversation: device-only AI; public source and GitHub Pages.
Stack: React/TypeScript/Vite, CodeMirror6, Mermaid, CSS, IndexedDB, Vitest, Playwright.

## Global Constraints
- No toolbar/sidebar/preview page. Markdown is canonical; no cloud content transmission.
- Preserve IME, selection, history and last valid diagram; only update changed diagrams.
- AI explicit invocation, parsed/previewed candidates and approval before application.
- No claims of real AI/IME/user testing without observed evidence.
- Local directory was empty. Create independent repository, never touch other projects.

## Review Focus
- Fences changed/deleted while render or AI is pending; identical diagrams have distinct identity.
- IME and history across hidden source and figure widgets.
- Malicious diagram/Markdown payloads and external resource fetches.
- Empty document, storage failure, import/export and rapidly queued saves.
- AI unavailable, download cancelled, invalid output and stale approved candidates.

### Task 1: Editor and persistence
- Establish project and test harness; write failing document/persistence and browser acceptance tests.
- Implement single CodeMirror document, Markdown decorations, Mermaid widgets and IndexedDB storage.
- Deliver text/diagram/text editing, sample on first open only, import/export.
- Verify with unit tests and Playwright basic editing and reload.

### Task 2: Editing quality
- Add render queue/generations/cache and error retention tests before implementation.
- Test focus, history, composition, resize/readability and block independence.
- Measure production input-to-paint for 10-node flowchart and 4-participant sequence, 30 edits each.
- Target warm p95 <=200ms; investigate >300ms. Record cold separately.

### Task 3: Local AI
- Add failing harness tests; implement Chrome LanguageModel provider, generation/repair, one retry.
- Use ja/en declarations, explicit model download, cancellation, candidate preview/diff and stale protection.
- Mock only model boundary in automated tests; real model validation is separate.

### Task 4: Publish and verify
- Run typecheck/lint/unit/build/browser suite, fresh-context review, fix important issues.
- New public repository canvas-mermaid-poc (date suffix on collision), GitHub Pages actions.
- Verify published app; never label deployment success from build alone.

### Task 5: Documentation and submission
- README, ARCHITECTURE, CURRENT, verification report; A4 one-page draft from observed facts.
- AI real-device verification blocked if model unavailable: current disk ~15GiB vs22GB initial requirement.
- CUA local Chrome disabled in Work settings; native IME cannot be claimed from synthetic tests.
- Official public site confirms Nov7; user-supplied23:59 JST/A4 rules provisional pending organizer template.
